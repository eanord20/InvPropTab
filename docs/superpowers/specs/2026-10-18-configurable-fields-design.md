# InvPropTab: дизайн настраиваемых полей

## Статус

Утверждён вариант B: декларативная конфигурация полей в JSON. Проект предназначен для Autodesk Inventor 2020, Windows x64 и .NET Framework 4.8. Публичный репозиторий распространяется по лицензии MIT.

## Цели

- Отключить историю и автодополнение для `Description`.
- Позволить пользователю добавлять и удалять поля панели, менять их порядок, видимость, подписи, тип редактора и значения списков.
- Сохранить работу со стандартными и пользовательскими iProperties Inventor.
- Не требовать прав администратора для установки и настройки.
- Обеспечить восстановление панели при отсутствующей или повреждённой конфигурации.

## Не входит в первую версию

- Поддержка Inventor новее 2020.
- Скрипты, вычисляемые поля и условия видимости.
- Синхронизация конфигурации через сеть.
- Автоматическое удаление пользовательских настроек и старого `descriptions.json`.

## Архитектура

### Конфигурация

Пользовательская конфигурация хранится в `%APPDATA%\InvPropTab\fields.json`. В сборке находится конфигурация по умолчанию. Если пользовательский файл отсутствует, создаётся его корректная копия. Если файл повреждён или имеет неподдерживаемую версию, панель загружает встроенную конфигурацию, пишет диагностическое сообщение и не перезаписывает повреждённый файл без подтверждения пользователя.

Корневая модель:

```json
{
  "version": 1,
  "fields": []
}
```

Поле содержит:

- `id` — стабильный уникальный идентификатор;
- `label` — отображаемая подпись;
- `source` — `standard`, `custom` или `system`;
- `propertySetId` — внутренний идентификатор набора свойств, если применимо;
- `propertyName` — имя iProperty;
- `editor` — `text`, `multiline`, `list`, `number` или `readonly`;
- `visible` — видимость;
- `order` — порядок;
- `values` — список значений только для редактора `list`;
- `rememberValues` — сохранение введённых значений только для редактора `list`.

Для `Description` заводская конфигурация использует `editor: text` и `rememberValues: false`. Введённые описания нигде отдельно не сохраняются.

### Компоненты

1. `FieldDefinition` и `FieldsConfiguration` описывают формат, не зависят от Inventor и UI.
2. `FieldsConfigurationStore` загружает, проверяет и атомарно сохраняет JSON.
3. `IPropertyAccessor` читает и записывает iProperties через стабильные идентификаторы наборов свойств; локализованные имена используются только как резервный путь.
4. `FieldEditorFactory` создаёт WinForms-редактор по `editor`.
5. `ConfigurableFieldsPanel` строит панель из отсортированных видимых определений.
6. `FieldsSettingsForm` редактирует копию конфигурации и применяет её только после успешной проверки.
7. Универсальное хранилище списков заменяет `SupplierStore`; история существует только у полей `list` с `rememberValues: true`.

### Поток данных

При активации документа менеджер передаёт контекст панели. Панель загружает проверенную конфигурацию, создаёт редакторы и читает значения из активного документа. Изменённые значения хранятся в UI до нажатия «Применить». При применении каждое поле валидируется и записывается через сервис свойств. Панель сообщает о полях, которые не удалось записать, и обновляет исходные значения только после успешной записи.

Настройки редактируются отдельно от документа Inventor. После сохранения конфигурации панель перестраивается и перечитывает значения активного документа.

## Проверка конфигурации

Конфигурация отклоняется, если:

- версия не поддерживается;
- `id` отсутствует или повторяется;
- `label` отсутствует;
- неизвестны `source` или `editor`;
- для редактируемого свойства отсутствует `propertyName`;
- `values` заданы для несовместимого редактора.

Повторяющиеся значения `order` не блокируют загрузку: применяется стабильная сортировка по `order`, затем по `id`; окно настроек нормализует порядок при сохранении. Неизвестные JSON-поля игнорируются для прямой совместимости.

## Ошибки и диагностика

Критические ошибки не подавляются пустыми `catch`. Технические детали записываются в `%APPDATA%\InvPropTab\invproptab.log`, пользователю показывается краткое сообщение. Ошибка одного поля не должна отменять успешно записанные поля, но итоговый результат обязан перечислять неуспешные операции.

JSON сохраняется атомарно: временный файл, проверка чтением, затем замена целевого файла.

## COM lifecycle

Владение COM-ссылками должно быть явным. Временные `PropertySet`, `Property`, `BrowserPane`, коллекции и параметры освобождаются в `finally`. Ссылки на панели удаляются при закрытии документа. При деактивации снимаются обработчики событий и освобождаются принадлежащие add-in COM-объекты. Принудительный `GC.Collect()` не используется как замена освобождению COM.

## Установщик

Inno Setup устанавливает add-in только для текущего пользователя:

- программа: `%LOCALAPPDATA%\Programs\InvPropTab`;
- manifest: `%APPDATA%\Autodesk\Inventor 2020\Addins`;
- настройки: `%APPDATA%\InvPropTab`;
- COM: `HKCU\Software\Classes`;
- архитектура: x64.

Установщик проверяет Inventor 2020, требует закрыть Inventor, поддерживает обновление и откат. Обычное удаление сохраняет настройки; полное удаление данных выполняется только по явному выбору.

## Тестирование

Автоматически тестируются модели и хранилище конфигурации, валидация, атомарное сохранение, сортировка полей и правило отсутствия истории у `Description`. Интеграционные проверки в Inventor 2020 охватывают детали, сборки, документы только для чтения, переключение и закрытие документов, повторный запуск, установку, обновление и удаление.

## Критерии готовности

- `Description` работает как текстовое поле и не создаёт историю.
- Поля можно полностью настроить через UI без ручного редактирования JSON.
- Повреждённая конфигурация не блокирует запуск панели.
- Inventor завершает работу без зависших COM-ссылок.
- Чистая установка выполняется без прав администратора.
- Репозиторий не содержит Autodesk DLL, результатов сборки и пользовательских данных.
